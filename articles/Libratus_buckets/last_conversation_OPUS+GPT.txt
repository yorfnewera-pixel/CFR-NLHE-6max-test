## О проекте

CFR-NLHE-6max-test — исследовательский проект по абстракции покера (6-max NLHE) с воспроизведением идей Libratus. Основные части:

- `native/hu20-buckets/` — Rust-крейт: кластеризация бакетов, EMD/CDF-метрики, OCHS-8, k-means, формат таблиц.
- `src/blueprint/equity_buckets.py` — Python-читатель таблиц (K50, HU20BKT1).
- `articles/Libratus_buckets/` — журнал экспериментов: `EMD.md`, отчёты PR A/PR B, спецификации.
- `docs/superpowers/specs/` и `docs/superpowers/plans/` — дизайн и планы этапов (PR A, PR B, ...).

Работа идёт поэтапно: PR A (OCHS-8) → PR B (малые таблицы) → PR C (запрещён до отдельного решения). После каждого этапа — остановка и внешнее ревью.

## Команды

```bash
# Rust: тесты крейта бакетов (основной suite)
cargo test -p hu20-buckets
# Только новые тесты этапа (пример PR B)
cargo test -p hu20-buckets libratus_bucket_table

# Python: тесты читателя бакетов
pytest -k libratus

# Форматирование
cargo fmt --check
```

- В выводе RED/GREEN должно быть видно, что запущено **больше 0 тестов**.
- Не использовать `--exact` с короткими фильтрами: `cargo test foo -- --exact` при отсутствии точного имени молча запускает 0 тестов и «проходит».
- Resource-heavy тесты ожидаемо `ignored` — это норма, их число указывать в отчёте.

## Жёсткие ограничения (нарушать нельзя)

- **Полный build запрещён** на этапах PR A/PR B. Разрешены только малые таблицы: малая колода `ranks=7`, `K=50` и `K=200`.
- **K=1 000 / K=5 000 и обучение (training) запрещены** до отдельного решения.
- **PR C не начинать** без явного разрешения. После отчёта PR B — остановиться.
- **Не менять K50, HU20BKT1, checkpoint и CFR.** Любая правка общего кода требует доказательства неизменности: побайтно равные SHA-256 таблиц или идентичный текст функции (`git diff` без фрагментов внутри `pub fn kmeans`).
- **Не менять существующий `--abstraction potential`.** Новый режим — только `--abstraction libratus-ochs` (таблица `LibratusBucketTable`, magic `HU20LIB1`). Имена `PotentialBucketTable`/`HU20POT1` не использовать.
- Правки общего кода (`first_minimum_emd`, `kmeans`) — только по уникальным якорям (сигнатуры функций или диапазон строк), чтобы патч не попал в идентичный блок K50.

## Соглашения по коду и экспериментам

- **Основной режим центров — взвешенное среднее CDF** (как в K50-контроле). Взвешенная покоординатная медиана — отдельный экспериментальный режим со своим именем в манифесте. Медиана **не** свойство Libratus или K50 — это решение проекта.
- **Медиана:** одно правило чётного веса на все координаты, закреплённое в манифесте; нижняя взвешенная медиана (`half_mass = (W+1)/2`). Центр обязан оставаться монотонной CDF с последним значением 1. Равные расстояния разрешаются через `first_minimum_emd` (меньший ID).
- **EMD-конвенция:** сумма `|ΔCDF|` **без** множителя 0,02. Зафиксировать до первой таблицы.
- **Tie-break:** проверять через публичный `kmeans_cdf` в обоих режимах, а не через вспомогательные функции.
- **Назначение после итераций:** `kmeans_cdf` обязан делать финальный проход назначения по итоговым центрам; `final_assignment_consistent == true`.
- **Одна реализация, не две:** не держать тестовую копию логики под `#[cfg(test)]`. Выносить итерации в обычную внутреннюю функцию (`kmeans_cdf_from_centroids`), median-ветка оставляет только инициализацию.
- **Инициализация mean и median** при одном seed — побайтно равные начальные центры (тест).
- **Пустой кластер** сохраняет прежний центр; правило сверять с поведением K50 и писать в манифест, число пустых кластеров — в отчёт.
- **Подвыборка:** при выборе пропорционально весу с возвращением k-means на ней **невзвешенный** (иначе вес учитывается дважды); при `N ≤ 20 000` берётся всё множество с весами. Фактическая схема PR B: начальная выборка `min(N, 200_000)`, итерации по полному множеству с весами.
- **Выбор рестарта:** минимальная взвешенная ошибка на полном малом множестве, при равенстве — меньший индекс рестарта. Правило в манифест.
- **Детерминизм:** одинаковые seed, подвыборка и рестарты дают одинаковые SHA-256 таблиц для обоих режимов.
- **Параметры первого малого прогона PR B:** `ranks=7`, seed `2026112101`, 3 рестарта, sample `min(20_000, N)`, максимум 50 итераций, порог `1e-4`.

## Метрики и отчёты

- Ошибку mean и median считать в **одной** метрике — L1 по CDF — и на **полном** малом множестве, а не только на подвыборке.
- Размеры бакетов давать **с весами**; указывать число пустых кластеров для каждого режима.
- Для river — отдельно взвешенная **L2**-ошибка и размеры бакетов.
- В отчёте PR B сравнить mean и median: ошибка внутри кластеров, размеры бакетов, число итераций, время. Потом остановиться.
- Отчёт PR A должен содержать: число прошедших тестов, напечатанные сертификаты, SHA commit.
- **Оговорка:** на `ranks=7` часть OCHS-групп физически отсутствует и заполняется через `uniform-equity-fill-v1`; качество river-кластеров на малой колоде не переносится на полную.

## Пустые группы OCHS (ворота)

- Ворота пройдены **сертификатом**, а не измерением: если в группе есть 8 попарно непересекающихся рук, то опустошающее её множество содержит ≥ 8 карт, а river удаляет ровно 7 (2 hero + 5 доски). Доля = ровно 0%.
- Тест `ochs_full_deck_groups_require_at_least_eight_removed_cards`: полная колода, 52-битовая маска, без `evaluate`, `count_ones() == 16`.
- Малая колода проверяет **только** корректность fallback `uniform-equity-fill-v1`; частоту определяет сертификат. В `EMD.md` раздел «Пустая группа после card removal» должен это отражать.

## Известные подводные камни

- Провал на `deck(5)`: в малой колоде только ранги T..A, группы 0,1,2,3,5 не появляются — 100% пустых групп ожидаемо и **ничего не говорит** о полной колоде.
- Патчи в median-ветку `kmeans_cdf` попадают и в `kmeans` из-за почти дословного совпадения тел — править по якорям и доказывать неизменность `pub fn kmeans`.
- `first_minimum_emd` используется в `kmeans_emd` (режим potential) — менять её нельзя без регрессии SHA-256 таблиц potential/K50.
- Регрессия turn-mean K=50 должна сравниваться с настоящим путём `--abstraction equity` (`equity-histogram-k50-v1`) на `ranks=7` с тем же seed и выборкой, **не** с `kmeans` (иначе тавтология). При несовместимости контроля — остановиться и сообщить.
- Сообщения commit — осмысленные (`docs: revise PR B plan`, `test: prove OCHS empty groups impossible on river`), не номера вроде «106», «107», «112», «113», «114».

## Процесс работы с Claude

- **Сначала план, потом код.** Для задач на несколько файлов — режим плана (`Shift+Tab` ×2), согласование, затем «выполни шаг 1».
- **Порядок этапов:** закрытие PR A — первым отдельным commit (прогон после `9550239`, восемь сертификатов, исправление `EMD.md`), затем PR B по задачам.
- **Одна задача — один commit.** RED-тест → GREEN → полный suite + `cargo fmt --check` → остановка и показ результата.
- **Не переходить к следующей задаче без проверки.** После Task 2 — стоп, после Task 3 — стоп, после отчёта PR B — стоп (PR C запрещён).
- **Критерий «готово»:** тесты проходят (с числом запущенных), нет новых зависимостей, K50/HU20BKT1/CFR не тронуты, `git diff` не содержит изменений в `pub fn kmeans`.
- **Ошибки — дословно.** Полный трассировочный стек, имя файла, строка — не пересказ.
- **Один этап — одна сессия.** Переходя от PR A к PR B, начинать с `/clear`; долговечный контекст переносит этот файл.
- Если ответ неверный — исправлять точечно («это меняет общий код, откати»), не переформулировать весь запрос.
