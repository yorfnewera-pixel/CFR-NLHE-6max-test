# Повторная проверка PR B — 24 ноября 2026

## Исправление от 25 ноября

Ниже в разделе 2 зафиксированы фактически выполненные подмены, но две из них не соответствовали плану: `false` был булевым значением, а `"123"` — строкой. Rust вправе их принимать. Требуемые проверки паритета используют JSON-строку `"false"`, число `-1` и число `123`; выводы раздела 2 не подтверждают результат Rust и не доказывают его некорректность.

## Итог

Повторная квалификация остановлена на воспроизведённых блокирующих замечаниях. Текущая ревизия `fa36515` не проходит пункты 1–3 плана Terra; свежие сборки по пункту 4 не запускались, поскольку сборщик всё ещё использует прежнюю turn-конфигурацию. PR C не начинать.

## 1. Кластеризация тёрна — НЕ ПРОЙДЕНО

В `native/hu20-buckets/src/main.rs` turn-манифест по-прежнему записывает `k50-weighted-sample-200000` и `restarts=1` (район строк 242–244). В `native/hu20-buckets/src/lib.rs` turn k-means по-прежнему формирует выборку `n.min(200_000)` (район строк 2057), а verified reader ожидает те же параметры (район строк 500). Следовательно, предел 20 000 и три детерминированных рестарта для K200 mean/K50 median не реализованы; обе ветки N<=20 000 и N>20 000 и выбор лучшего рестарта по общей взвешенной L1 здесь не могут считаться проверенными.

K50 mean остаётся отдельным контрольным режимом. Сохранённые таблицы `release1` и `release2` имеют совпадающие SHA-256 по всем четырём mean-файлам (turn K50/K200 и river K50/K200), но это повторная сверка старых артефактов, не повторная сборка и не новый побайтный тест с текущей реализацией старого сборщика.

## 2. Rust/Python манифест — НЕ ПРОЙДЕНО

Профильные тесты: `cargo test --offline --manifest-path native/hu20-buckets/Cargo.toml libratus -- --nocapture` — 17 passed, 2 ignored; `python -m pytest tests/test_equity_buckets.py -k libratus -q` — 14 passed. Они не закрывают выявленные негативные варианты.

Эксперимент на таблице `results/libratus-pr-b/release1/libratus-river-k50.bin` с валидным `release1/libratus-river-k50.json`: Python принял отдельные подмены `working_tree_dirty=false`, `seed=-1`, `code_revision="123"`. Эти результаты не устанавливают паритет читателей на вариантах, указанных в плане; Rust-типизация принимает булево `false` и непустую строку `"123"`.

## 3. Публичные читатели HU20LIB1 — НЕ ПРОЙДЕНО

Python `LibratusBucketTable(table_path)` без `manifest_path` успешно открыл сохранённый файл. Rust предоставляет `LibratusBucketTable::read(path)`, который вызывает только `parse_bytes`; полноценная проверка доступна отдельно через `read_verified(path, manifest_path)`. Поэтому публичные пути чтения пропускают проверку манифеста, SHA-256 и отпечатка полного набора классов.

Для каждого читателя остаётся обязательным проверить отказ в трёх сценариях: нет манифеста; изменён байт ID; удалён класс при пересчитанных счётчике и SHA-256. Последний случай не проверен на всех публичных путях.

## 4. Повторная сборка и профильный прогон — НЕ ВЫПОЛНЕНО

Новые сборки `ranks=7`, K=50/200 с одинаковым seed не запускались: конфигурация builder заранее не соответствует контракту пункта 1. SHA-256 сохранённых старых таблиц release1/release2 совпали между каталогами. Linux CI в этой проверке не перезапускался; его результат ранее записан в EMD.md и не является свежим результатом этой квалификации.
