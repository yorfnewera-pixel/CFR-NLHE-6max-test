# PR C: сквозная проверка HU20 + V1

База до PR C — `7696cf3`. Первый коммит схемы PR C — `7f93243`.
Полная сборка таблиц и обучение не запускались.

## Сквозной тест

Rust загрузил turn и river из малых таблиц PR B с обязательной проверкой
манифестов, восстановил сохранённую запись checkpoint без итераций CFR,
повторно сохранил состояние и сравнил распакованное содержимое побайтно.
Export создан из восстановленного checkpoint и открыт обычным
`FrozenBlueprint` с настоящим `Checkpoint`. Rust сохранил запись по ключу
флопа фиксированной раздачи. Python нашёл эту запись и вернул единичную
вероятность первого действия и нулевые вероятности остальных. На трёх
других улицах записей нет, там проверен резервный ответ. Усиленный тест
падает на прежнем экспорте с искусственным ключом.
Повреждённая таблица, другая валидная пара K200 и меню V2 отвергнуты;
несовпадение меню или таблиц в Rust проверяется до чтения записей состояния.

Малые таблицы допускаются только в тесте: Rust использует `#[cfg(test)]`
вход, Python временно подменяет проверку допустимой колоды в тестовом процессе.
Оба пути при этом вызывают существующие строгие читатели манифестов и таблиц.
Рабочие загрузчики отклоняют малую колоду; неподтверждённая `ranks=13`
также отвергается. Поэтому полноценный рабочий resume новой схемы остаётся
недоступен до отдельной квалификации полной колоды.

В штатном CLI добавлен `--libratus-buckets` для HU20/V1; проверены отказы
для меню V2 и неподходящей колоды. Не подключённые к схеме search, LBR,
каталог арены и web явно отказывают. Bench отвергает этот аргумент на этапе
разбора команд.

## Результаты в WSL

- Rust: пять адресных тестов, один отдельный сквозной тест и один тест CLI.
- Python: 78 тестов, один исключён; включая загрузку экспорта, подмены,
  отказы неподдерживаемых потребителей и проверки старых читателей.
- Дополнительно: три теста паритета существующих v1 и K50 на обновлённой
  Linux-сборке. Контрольный K50-checkpoint был проверен потоково ранее;
  повторное обучение или восстановление всех его записей в память не проводилось.

## Повторный запуск сквозной проверки

Тест зависит от локальных игнорируемых артефактов PR B и не запускается
обычным CI автоматически. Должны существовать каталоги `T` и `U` с файлами
`libratus-{turn,river}.{bin,json}`: в `T` — K50 из
`results/libratus-pr-b/release1`, в `U` — K200 из
`results/libratus-pr-b/recheck-20261125-a`. Их следует копировать в новые
тестовые каталоги, не перезаписывая исходные таблицы.

В WSL из корня проекта с установленными Cargo и проектными зависимостями Python:

```bash
export HU20_LIBRATUS_TEST_DIR="$PWD/native/hu20-trainer/target/prc-e2e-20261127"
export HU20_LIBRATUS_OTHER_TEST_DIR="$PWD/native/hu20-trainer/target/prc-e2e-other-20261127"
export CARGO_TARGET_DIR=native/hu20-trainer/target/wsl-prc
cargo test --offline --manifest-path native/hu20-trainer/Cargo.toml --lib libratus_сквозное_восстановление_проверенных_таблиц -- --ignored
native/hu20-trainer/target/prc-py311/bin/python -m pytest -q tests/test_libratus_pr_c.py tests/test_equity_buckets.py -k 'not native_evaluator'
```

Тест создаёт `checkpoint.gz`, `resumed.gz` и `policy.gz` внутри `T`.
Каталоги `T` и `U` следует использовать только как тестовые копии.

## Побайтная совместимость v1 и K50

В WSL собраны две копии Rust-кода. Первая получена через `git archive`
из `7696cf3`, во вторую скопированы изменения PR C. Один и тот же
тестовый пример раздал колоду с ID карт от 0 до 51, дошёл до ривера
через call и check, записал по одному узлу на улицу с заданными regret
и average и вызвал `save_recoverable` и `export`. Тестовые K50-таблицы
созданы через `tests.native_equity_tables.write_tables` для этой колоды.
Итераций CFR не было. Локальный сценарий и пример находятся в
`native/hu20-trainer/target/prc-byte-check`.

`cmp` подтвердил равенство восьми ключей и их payload и распакованного
содержимого четырёх файлов. SHA-256 одинаковы для обеих сборок.

Пиковая память не измерялась. Отдельный сквозной Rust-тест занял 1,50 с,
финальный прогон Python занял 3,99 с. Локальные артефакты остаются в
игнорируемом каталоге `target`. Решение по локальной проверке — передать PR C
в Linux CI, сохранив ограничение на рабочую загрузку до квалификации полной колоды.
