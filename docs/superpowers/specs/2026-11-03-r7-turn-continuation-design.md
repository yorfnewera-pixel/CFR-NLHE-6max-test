# R7 turn continuation: design

## Цель

Однократно проверить, достигает ли turn-кластеризация строгой финальной
согласованности после production-ранней остановки на шаге 28, не меняя
production-путь и не строя flop.

## Границы

Только ignored test-only Rust-тест на `TestOnlyEmdStepper`, `ranks=7`, `K=10`,
seed `202610050003`, два Rayon-потока. Путь выполняет один replay river+turn
шагов 1–28; полученное состояние является новой проверяемой исходной точкой,
а не восстановленным историческим checkpoint.

## Выбранный подход

Использовать существующий stepper, который содержит assignments, биты центров,
RNG и диагностику. Для probe добавить test-only шаг без установки флага
ранней стабилизации. После каждого update записывать атомарный checkpoint и
выполнять немутирующую финальную диагностику. До continuation сверить
неокруглённые objectives с `summary.json`, а свежую полную финальную
диагностику шага 28 — только с округлённым форматом `stderr.log`; расхождение
завершает probe до шага 29.

## Инварианты

- Не менять production-код, его метрику, обновление центров, tie-breaking,
  допуски или правило остановки.
- Не запускать flop и не записывать production-таблицы.
- Один общий timeout 300 с, без повторов.
- Продолжение прекращается при нулевой финальной диагностике, повторе полного
  состояния, шаге 50, ошибке или timeout.
- В отчёте численное совпадение replay отделяется от побитовой проверки новых
  checkpoint-состояний.
