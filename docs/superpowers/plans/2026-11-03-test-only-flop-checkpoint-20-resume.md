# План continuation test-only checkpoint-20

> **Для агентных исполнителей:** обязательный поднавык — `superpowers:executing-plans`; шаги отмечаются флажками.

**Цель:** один раз продолжить flop из checkpoint шага 20 максимум до общего шага 30, не повторяя шаги 1–20.

**Архитектура:** В `#[cfg(test)]` добавить загрузку полного состояния доступных checkpoint 18–20 после восстановления точных входов. Новый ignored resume-test проверяет каждый checkpoint до stepper, продолжает только 21–30, сравнивает полные состояния с историей и всегда выполняет немутирующую финальную диагностику при ранней остановке либо шаге 30.

**Технологии:** Rust/Cargo release tests, PowerShell Windows Job Object.

**Спецификация:** подтверждённое пользователем ТЗ текущего чата; `web_reports/potential-emd-r6-k20-flop-trajectory-probe-20261103.md`.

## Глобальные ограничения

- Только test-only код и документация; не менять production-путь, launcher, метрику, центры, допуски и таблицы.
- Один запуск: два Rayon-потока, timeout 300 с, новый пустой каталог; release-сборка после последней правки и до запуска.
- SHA-256, шаг, размерности и fingerprint каждого checkpoint проверяются до continuation; при ошибке запуск с нуля запрещён.
- Восстановление river/turn входов входит в timeout; flop-шаги 1–20 не запускаются.

## Фокус ревизии

- История циклов использует `state_words` полных checkpoint 18–20, а не fingerprint.
- Ранняя остановка отмечается отдельно от достижения шага 30 и всё равно получает final diagnostic.
- Checkpoint 21–30 пишутся атомарно после update.
- После timeout отсутствуют дочерние процессы, последний checkpoint доступен.
