# EMD Production Contract Proposal

**Цель:** безопасно заменить per-edge фильтр `1e-9`, гарантируя выход с результатом либо типизированной ошибкой, но не обещая успех для каждого допустимого `f64` входа.

**Минимальный diff:** в `try_emd` считать residual capacity допустимой при `> 0.0`; вычислять bottleneck только по capacities найденного пути, а не по `required_mass - delivered`; определять успех и прогресс по residual-графу. Сохранить `try_emd -> Result<f32, EmdError>` и существующее обогащение `EmdContextError`; launcher получает неуспешный процесс/статус при `Err`, без panic и без таблиц/успешного `status.json`.

**Успех:** только если суммы source residual и demand residual не больше tolerance, доставленная масса, выведенная из source residual, согласована с требуемой, а стоимость конечна. Накопленный `delivered` не является критерием успеха: положительная augmentation может изменить residual-граф, но не изменить эту сумму из-за округления `f64`. Для нормированных `f32` распределений в масштабе единицы используется `tolerance = 64 * f64::EPSILON * dimension`: это консервативная граница порядка операций `f64`, не допуск на пользовательскую массу. Для ненормированного внешнего API сначала выполняется текущая нормировка; при другом масштабе либо иной арифметике допуск нужно пересмотреть.

**Защитные исходы:** `NoPath` — sink недостижим; `NoProgress` — amount не положителен/неконечен либо не изменяет ни одну forward/reverse residual capacity пути; `IterationLimit` — исчерпан конечный бюджет без полного residual-транспорта; `IncompleteTransport` — цикл завершился, но не выполнены проверки residual-транспорта. Ни один не возвращает частичную стоимость как `Ok`.

**Бюджет:** `4 * (2 * dimension + 2)^2` итераций. Это квадратичный диагностический предохранитель относительно числа вершин residual-графа: достаточный запас для малых test-only случаев, но только гарантия выхода с ошибкой, не доказательство успешного решения всех допустимых задач.

**Критерии приёмки:** fixture ranks=5, fixture `point=1`/`centroid=9` и малые остатки завершаются на production-пути с oracle-cost; invalid input остаётся `Err`; тесты покрывают `IterationLimit`, `NoProgress` и `NoPath` через test-only инъекции; launcher не записывает успешный статус при любой `Err`; полный `cargo test`, `cargo fmt --check`, `git diff --check` зелёные.

**Ограничение:** до отдельного согласования production-патча нет доказательства, что `f64` solver всегда достигает успеха до бюджета.
